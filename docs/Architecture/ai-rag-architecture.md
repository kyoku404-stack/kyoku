## 1. Executive Summary

The KEEP AI Engine delivers context-aware, enterprise-grade decision support and conversational intelligence. Unlike naive RAG systems that rely solely on simple cosine similarity over vector chunks, KEEP implements a **Multi-Stage Hybrid Retrieval & Reranking Architecture** coupled with **Citation Provenance** and **Knowledge Graph Augmented Context**.

## 3. Core Algorithms & Mathematics

### 3.1 Reciprocal Rank Fusion (RRF)
To combine dense vector search rankings $R_{\text{dense}}$ and sparse keyword search rankings $R_{\text{sparse}}$ without score scale distortion, KEEP employs RRF:

$$\text{RRF\_Score}(d) = \sum_{m \in \{\text{dense}, \text{sparse}\}} \frac{1}{k + r_m(d)}$$

Where:
- $r_m(d)$ is the rank position of document chunk $d$ in system $m$ (1-indexed).
- $k$ is a smoothing constant, defaulted to $60$.

### 3.2 Dynamic Cross-Encoder Reranking
Top $N = 25$ candidate chunks from RRF are evaluated through a cross-encoder model:
$$\text{Score}_{\text{rerank}} = \text{CrossEncoder}(\text{Query}, \text{Chunk}_{\text{text}})$$
The top $K = 5$ scoring chunks are selected for context window assembly.

## 4. Citation & Source Provenance Standard

Every claim generated by the LLM must be backed by a verifiable citation tag:
- **Format**: `[Doc: <document_id>, Page: <page_number>, Chunk: <chunk_index>]`
- **Verification**: The RAG service parses all generated tags and verifies they map directly to retrieved chunks passed in the context.
- **Payload Schema**:
```json
{
  "query": "What were Q3 sales milestones?",
  "answer": "Q3 sales reached $12M exceeding the target by 15% [Doc 101, Page 4].",
  "citations": [
    {
      "document_id": "doc_101",
      "filename": "Q3_Financial_Summary.pdf",
      "page_number": 4,
      "snippet": "...Q3 revenue totaled $12,000,000 against a $10,400,000 target...",
      "relevance_score": 0.94
    }
  ],
  "confidence_score": 0.96
}
```

## 5. Knowledge Graph Integration (Phase 2.4 Baseline)

- **Entity Model**: Nodes represent enterprise objects (`Person`, `Department`, `Project`, `Document`, `Policy`).
- **Relationship Model**: Edges represent semantic connections (`AUTHOR_OF`, `ASSIGNED_TO`, `BELONGS_TO`, `DEPENDS_ON`, `SUPERSEDES`).
- **Query Augmentation**: When a query references a specific entity (e.g. "Project Apollo"), the graph engine traverses 1-hop and 2-hop neighbors to inject relationship context into the prompt alongside document chunks.

## 6. Abstract AI Service Interfaces

To avoid vendor lock-in, all AI services implement strict abstract interfaces:
- `BaseEmbeddingService`: Abstract `embed_documents()` and `embed_query()`.
- `BaseRetriever`: Abstract `retrieve(query: str, top_k: int, organization_id: UUID)`.
- `BaseReranker`: Abstract `rerank(query: str, chunks: List[DocumentChunk])`.
- `BaseLLMService`: Abstract `generate(prompt: str, context: List[DocumentChunk])` and `generate_stream(...)`.
